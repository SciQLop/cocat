# Self-service rooms, phases 0–1: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Harden the server (phase 0). Then replace "a room is a string on the user row" with real rooms, members, roles and invitations behind a REST API (phase 1).

**Architecture:** Service modules (`rooms.py`, `invitations.py`) hold all rules. They take an `AsyncSession` and commit once per public call. A thin FastAPI router (`routes.py`) maps them to `/api` and turns service exceptions into HTTP codes. The schema is managed by Alembic migrations shipped inside the package. They run at server start. A small registry of open websockets lets the server disconnect people when they lose access.

**Tech Stack:** FastAPI, fastapi-users 15, SQLAlchemy 2 async over aiosqlite, Alembic (new), pytest with Starlette's `TestClient` for in-process HTTP and websocket tests.

**Spec:** `docs/superpowers/specs/2026-11-04-self-service-rooms-design.md` (phases 0 and 1 only; phases 2–6 get their own plans).

**Review history:** revised after an independent review (opencode, 2026-11-04). The main changes: the `user.rooms` column is no longer dropped; invitation tokens moved out of URLs; invitation acceptance is atomic; non-members get 404; legacy room ids keep their files; open sockets are kicked on removal (Task 9).

## Global Constraints

- Python ≥ 3.10. CI runs 3.10–3.14 on Linux, macOS and Windows.
- `coverage report --fail-under=100` must hold. New code is tested in-process, so it is measured. Do **not** add `# pragma: nocover` to new code.
- `ruff check src tests`, `ruff format --check src tests` and `mypy src tests` must pass (ruff 0.17.3).
- Run tests with the venv on `PATH`, because the server tests spawn the `cocat` CLI: `export PATH=$PWD/.venv/bin:$PATH`.
- One build or test run at a time, in the foreground. Never start a second test run while one is going.
- The existing websocket route `/room/{room_id}` and `GET /rooms` keep their URLs and response shapes. The deployed SciQLop plugin depends on them.
- Roles: `owner`, `editor`, `viewer`. Phase 1 APIs only *accept* `editor` as an assignable role: viewers can't be enforced until phase 5.
- Registration stays superuser-only in this plan, so it isn't rate-limited yet. It opens, with a rate limit, in phase 3 together with email verification.
- No secret (password, JWT, reset token, invitation token) is ever printed, logged, or placed in a URL path.
- Datetimes in the DB are naive UTC. Always get "now" from `utcnow()` in `db.py`, never from `datetime.now()` directly.
- Tasks 4–9 ship as **one release**. They can be separate commits but not separate deploys, because the CLI and the API disagree about room access between Task 4 and Task 8.
- `*.secret` files must never be committed. Add `*.secret` to `.git/info/exclude` locally; there's no `.gitignore` in this repo.

## Review Focus

1. **A deployed DB created by today's code** (tables exist, no `alembic_version`, `user.rooms` filled) must upgrade without losing users or room access, and a failed upgrade must be safe to retry. Test owner: Task 4.
2. **Two users sharing an email prefix** (`john@a.org`, `john@b.org`) both have room `john` today. After migration they must still both reach it: we can't split data that is already merged. Test owner: Task 4.
3. **Two people accepting the same single-use invitation at once**: only one gets in, and `uses` ends at 1. Expired or revoked invitations are refused at accept time too. Test owner: Task 6.
4. **The owner trying to leave, or be demoted or removed**, must be refused with 409. Otherwise a room ends up with no owner. Test owner: Task 5.
5. **A member removed while connected** loses the socket immediately and can't reconnect. Test owner: Task 9.

### Task 5: Room service

**Files:**
- Create: `src/cocat/app/rooms.py`, `tests/test_rooms.py`

**Interfaces:** every function is `async` and takes `session: AsyncSession` first. Public mutating functions commit once at the end. The `_`-prefixed helpers never commit, so callers can compose them in one transaction.

- Errors: `class RoomError(Exception)`, with subclasses `NotFound`, `Forbidden` and `Conflict`.
- `validate_room_id(room_id: str) -> str` (sync): `^[A-Za-z0-9_-]{1,64}$`, else `ValueError`. It applies to **new** ids only (CLI `create-room --room-id`). Generated ids are `uuid4().hex`. Legacy ids are never re-validated.
- `create_room(session, owner: User, name: str, room_id: str | None = None) -> Room`. Raises `Conflict` if the id exists.
- `create_personal_room(session, user: User) -> Room`. The name is `"Personal"`.
- `get_role(session, room_id: str, user_id: UUID) -> Role | None`
- `require_role(session, room_id: str, user: User, minimum: Role) -> Role`.
  - Raises `NotFound` if the room doesn't exist **or the user isn't a member**. Both look the same, so legacy ids, which are guessable email prefixes, don't reveal which rooms exist.
  - Raises `Forbidden` only for a member whose role ranks below `minimum`.
- `list_user_rooms(session, user_id: UUID) -> list[tuple[Room, Role]]`, sorted by `Room.name`, then `Room.id`.
- `_add_member(session, room_id: str, user_id: UUID, role: Role) -> Role`, no commit. It keeps the higher of the existing and new roles and returns the result. `add_member(...)` is the same plus a commit.
- `rename_room(session, room_id, actor: User, name: str) -> Room` (owner)
- `delete_room(session, room_id, actor: User) -> None` (owner)
- `list_members(session, room_id, actor: User) -> list[tuple[User, Role]]` (any member), sorted by email.
- `set_member_role(session, room_id, actor: User, member_id: UUID, role: Role) -> None` (owner).
  - Raises `NotFound` if `member_id` isn't a member. It must never add one.
  - Raises `Conflict` if `role is Role.owner` or if the target is the owner.
- `remove_member(session, room_id, actor: User, member_id: UUID) -> None`.
  - The owner may remove anyone but themselves.
  - Any member may remove themselves, which is leaving.
  - Removing the owner raises `Conflict`. Others get `Forbidden`.
- `transfer_ownership(session, room_id, actor: User, new_owner_id: UUID) -> None` (owner). The target must be a member (`NotFound` otherwise). The old owner becomes `editor`.
- `set_owner(session, room_id: str, new_owner_id: UUID) -> None`: an admin operation with no actor check, used only by the CLI. The new owner must already be a member, and the previous owner becomes `editor`.

### Task 6: Invitation service

**Files:**
- Create: `src/cocat/app/invitations.py`, `tests/test_invitations.py`

**Interfaces:**
- Consumes: `require_role`, `_add_member`, `NotFound`, `Forbidden`, `Conflict` from `rooms.py`; `utcnow` from `db.py`.
- `INVITATION_LIFETIME = timedelta(days=14)`
- `hash_token(token: str) -> str`: plain SHA-256 hex. The token carries 256 random bits and is looked up by its hash, so a salt would break the lookup.
- `@dataclass(frozen=True) class InvitationPreview` with `room_id: str`, `room_name: str`, `role: Role`, `inviter_email: str | None`, `expires_at: datetime`.
- `_valid_invitation_filter(now: datetime)`: the one SQL predicate that defines "valid": `revoked IS false AND expires_at > now AND (max_uses IS NULL OR uses < max_uses)`. Preview and accept both use it, so the check is literally the same code.
- `create_invitation(session, room_id, actor: User, role: Role, email: str | None = None, expires_in: timedelta = INVITATION_LIFETIME, max_uses: int | None = None) -> tuple[Invitation, str]`.
  - Requires the owner, and raises `Conflict` for `Role.owner`.
  - An email invitation forces `max_uses = 1`.
  - The raw token is `secrets.token_urlsafe(32)`. Only its hash is stored.
  - Returns the row and the raw token. The raw token is shown once; an owner who loses it creates a new link.
- `preview_invitation(session, token: str) -> InvitationPreview`. Raises `NotFound` for unknown or invalid tokens. All cases look the same, so the response doesn't reveal which.
- `accept_invitation(session, token: str, user: User) -> Room`, in one transaction:
  1. Load the invitation through the valid filter (`NotFound` otherwise). An email mismatch (compared case-insensitively) raises `Forbidden`.
  2. Run `UPDATE invitation SET uses = uses + 1 WHERE id = :id AND <valid filter>`. If `rowcount != 1`, raise `NotFound`. That conditional update is what stops two concurrent accepts of a single-use link.
  3. `_add_member(...)`, then one commit.
- `list_invitations(session, room_id, actor: User) -> list[Invitation]` (owner). Only valid ones (same filter), newest first.
- `revoke_invitation(session, room_id, actor: User, invitation_id: int) -> None` (owner). Raises `NotFound` if the id belongs to another room.
