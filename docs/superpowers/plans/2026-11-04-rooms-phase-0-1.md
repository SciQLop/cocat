# Self-service rooms, phases 0–1: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Harden the server (phase 0). Then replace "a room is a string on the user row" with real rooms, members, roles and invitations behind a REST API (phase 1).

**Architecture:** Service modules (`rooms.py`, `invitations.py`) hold all rules. They take an `AsyncSession` and commit their own changes. A thin FastAPI router (`routes.py`) maps them to `/api` and turns service exceptions into HTTP codes. The schema is managed by Alembic migrations shipped inside the package. They run at server start.

**Tech Stack:** FastAPI, fastapi-users 15, SQLAlchemy 2 async over aiosqlite, Alembic (new), pytest with Starlette's `TestClient` for in-process HTTP tests.

**Spec:** `docs/superpowers/specs/2026-11-04-self-service-rooms-design.md` (phases 0 and 1 only; phases 2–6 get their own plans).

## Global Constraints

- Python ≥ 3.10. CI runs 3.10–3.14 on Linux, macOS and Windows.
- `coverage report --fail-under=100` must hold. New code is tested in-process, so it is measured. Do **not** add `# pragma: nocover` to new code.
- `ruff check src tests`, `ruff format --check src tests` and `mypy src tests` must pass (ruff 0.17.3).
- Run tests with the venv on `PATH`, because the server tests spawn the `cocat` CLI: `export PATH=$PWD/.venv/bin:$PATH`.
- One build or test run at a time, in the foreground. Never start a second test run while one is going.
- The existing websocket route `/room/{room_id}` and `GET /rooms` keep their URLs and response shapes. The deployed SciQLop plugin depends on them.
- Roles: `owner`, `editor`, `viewer`. Phase 1 APIs only *accept* `editor` as an assignable role: viewers can't be enforced until phase 5.
- Registration stays superuser-only in this plan. It opens in phase 3, together with email verification.
- No secret (password, JWT, reset token, invitation token) is ever printed or logged.

## Review Focus

1. **A deployed DB created by today's code** (tables exist, no `alembic_version`, `user.rooms` filled) must upgrade without losing users or room access. Test owner: Task 4.
2. **Two users sharing an email prefix** (`john@a.org`, `john@b.org`) both have room `john` today. After migration they must still both reach it: we can't split data that is already merged. Test owner: Task 4.
3. **An expired, revoked or used-up invitation** must be refused at accept time, not only at preview time. Test owner: Task 6.
4. **The owner trying to leave, or be demoted or removed**, must be refused with 409. Otherwise a room ends up with no owner. Test owner: Task 5.
5. **A removed member reconnecting** to the websocket must be refused. The check reads the membership table on each connect. Test owner: Task 7.

### Task 5: Room service

**Files:**
- Create: `src/cocat/app/rooms.py`, `tests/test_rooms.py`

**Interfaces** (every function is `async` and takes `session: AsyncSession` first; mutating ones `await session.commit()`):
- Errors: `class RoomError(Exception)`, with subclasses `NotFound`, `Forbidden` and `Conflict`.
- `validate_room_id(room_id: str) -> str` (sync) checks `^[A-Za-z0-9_+-][A-Za-z0-9._+-]{0,63}$` and raises `ValueError`. The pattern accepts every email prefix seen today and rejects `..`, `/` and leading dots.
- `create_room(session, owner: User, name: str, room_id: str | None = None) -> Room`. The id defaults to `uuid4().hex`. It raises `Conflict` if the id exists.
- `create_personal_room(session, user: User) -> Room`. The name is `"Personal"`.
- `get_role(session, room_id: str, user_id: UUID) -> Role | None`
- `require_role(session, room_id: str, user: User, minimum: Role) -> Role`. It raises `NotFound` if there's no such room, and `Forbidden` if the user isn't a member or ranks below `minimum`.
- `list_user_rooms(session, user_id: UUID) -> list[tuple[Room, Role]]`, sorted by `Room.name`, then `Room.id`.
- `add_member(session, room_id: str, user_id: UUID, role: Role) -> Role`. It keeps the higher of the existing and new roles and returns the resulting role.
- `rename_room(session, room_id, actor: User, name: str) -> Room` (owner)
- `delete_room(session, room_id, actor: User) -> None` (owner)
- `list_members(session, room_id, actor: User) -> list[tuple[User, Role]]` (any member), sorted by email
- `set_member_role(session, room_id, actor: User, member_id: UUID, role: Role) -> None` (owner). It raises `Conflict` if `role is Role.owner` or if the target is the owner.
- `remove_member(session, room_id, actor: User, member_id: UUID) -> None`. The owner may remove anyone but themselves. Any member may remove themselves, which is leaving. Removing the owner raises `Conflict`. Others get `Forbidden`.
- `transfer_ownership(session, room_id, actor: User, new_owner_id: UUID) -> None` (owner). The target must be a member (`NotFound` otherwise). The old owner becomes `editor`.

### Task 6: Invitation service

**Files:**
- Create: `src/cocat/app/invitations.py`, `tests/test_invitations.py`

**Interfaces:**
- Consumes: `require_role`, `add_member`, `NotFound`, `Forbidden`, `Conflict` from `rooms.py`.
- `INVITATION_LIFETIME = timedelta(days=14)`
- `hash_token(token: str) -> str`: SHA-256 hex.
- `@dataclass(frozen=True) class InvitationPreview` with `room_id: str`, `room_name: str`, `role: Role`, `inviter_email: str | None`, `expires_at: datetime`.
- `create_invitation(session, room_id, actor: User, role: Role, email: str | None = None, expires_in: timedelta = INVITATION_LIFETIME, max_uses: int | None = None) -> tuple[Invitation, str]`. It requires the owner, and raises `Conflict` for `Role.owner`. An email invitation forces `max_uses = 1`. The raw token comes from `secrets.token_urlsafe(32)`; only its hash is stored. It returns the row and the raw token.
- `preview_invitation(session, token: str) -> InvitationPreview`. It raises `NotFound` when the token is unknown, revoked, expired, or has `uses >= max_uses`. The same `NotFound` is used in all four cases, so the response doesn't reveal which.

- `list_invitations(session, room_id, actor: User) -> list[Invitation]` (owner). It excludes revoked ones and lists newest first.
- `revoke_invitation(session, room_id, actor: User, invitation_id: int) -> None` (owner). It raises `NotFound` if the id belongs to another room.
